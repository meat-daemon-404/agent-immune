## 标题

```
我回放了自己 4 个月、2 万次 Coding Agent 工具调用，然后写了个零依赖的"免疫系统"，让 agent 别再重复踩同一个坑
```

## 正文

先说背景：我日常同时用 ZCode（Claude Code 的一个分支）和 Codex CLI 干活。用得越久越明显的一个现象是——agent 上周踩过的坑、查过的问题、修好的东西，这周换个会话**原样再踩一遍**。不是它不会，是没人把"这次的教训"送到"下一次调用"面前。

于是我做了个实验：什么都不改，先量化。把 4 个月的真实会话历史回放给一条简单的配对规则——**一次调用失败，之后对同一目标的调用成功了，这就是一条教训**：

- 19,971 次工具调用 · 835 次失败 · **172 次"失败→修复成功但没人记住"**
- 最高频的全是熟面孔：「File has not been read yet」83 次、「File has been modified since read」63 次、一个 shell 误用家族 101 次
- 按中位请求大小 × 每次事件 2 个来回估算，约 **3,400 万 token** 花在了本可避免的重复上（估算假设只有这一条，没有编造汇率）

然后才动手写工具。**dsh-immune-system** 的工作方式：

1. **从证据学习，不从聊天记录学习**：一条规则存在的前提是某次调用真的失败了、某个具体动作真的修好了它——修的时候改了哪些文件也作为出处一并记录
2. **在重复之前注入**：匹配到的规则在下一次调用前进上下文，而不是等你想起去搜索
3. **零依赖**：只用 Node 内置 `node:sqlite`，FTS5 trigram 索引 + 中文双字回退（中文触发词实测可用）
4. **宿主全覆盖**：Claude Code / Codex CLI 用 `npx dsh-immune-system@latest connect claude-code` 一条命令接入（装到固定路径 `~/.dsh-immune/`，npx 缓存清理不会弄断钩子，`--remove` 卸载干净）；Cursor/Cline 走 MCP；DSH/ZCode 原生插件安装
5. **10 秒冷启动**：`audit --dry-run` 把你自己的历史变成一份可截图的踩坑报告 + 首批规则；`seed git-safety` 装六条手写的保命规则（卸载时，agent 已经用过的规则会保留——那已经是你的证据了）
6. **全部本地 SQLite，无遥测**；`immune ui` 有个本地仪表盘，能看注入计数和跨模型归因

判定准确性说清楚：回放 20,100 次带宿主标注的真实调用，判定器与宿主标注一致率 97.54%、**假阴性 0**；2.46% 的假阳性全是"非零退出本来就是想要的答案"的探针类命令——这个类别我们量化后接受了，没有用输出正则去硬补。
