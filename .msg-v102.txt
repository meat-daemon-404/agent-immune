fix(test): the rerank test must not depend on insertion milliseconds

The rerank test failed on CI-Linux only: two rules inserted back to back get
timestamps one millisecond apart, and time decay turned that into a ranking
difference the test never intended to measure. Equalising both rows'
updated_at/created_at pins the assertion to what it means to test — that two
matched windows outrank one — instead of the machine's clock.

CI also caught the two POSIX path bugs in the self-noise walk (dirname on a
backslash path returns '.' on Linux, and a drive root resolved against the
process's drive-relative cwd), both fixed in the previous commit; the full CI
matrix is green now except this pinned-clock assertion, which this commit
makes deterministic.
